# Quirkbench 1.3 roadmap

Make live investigations reliable through disconnection, preserve fleeting evidence,
and reduce routine setup. Keep one foreground controller, existing command ownership,
recovery and transfers. The software changes below are implemented. Hardware checks remain separate.

## Evidence and decisions

Review covers all seven open issues and their comments on October 24, 2026. The
latest overnight investigation completed custom-kernel deployment and returned
940 files with no reported collection problems. Preserve that working journey.
Session discovery and command observation failed; progress rendering was visibly
corrupted. Capture, keep-awake and desktop delivery are useful additions, not proof
that Quirkbench caused the investigated hardware symptoms. #241 identifies real
argument drift, but its adapter-expansion remedy is superseded by removing sequences.

## Correctness first

**Sessions (#237).** Use repeated `loginctl` property options, verified against the
reported output. Preserve useful errors instead of converting every failure to an
empty list. Tolerate a session genuinely ending during inspection. Reuse the selected
user's environment and existing deadlines; no autologin, new accounts or VT switching.

**Observation (#238).** Identify the failing parser boundary before choosing a fix.
Both SSH replies and saved metadata are candidates; atomic file replacement already
exists. Record phase, command/run/boot and bounded diagnostic detail without dumping
secrets or entire output. Distinguish transport loss, invalid responses and damaged
saved records from experiment failure. Never silently treat malformed data as success.

Add an opt-in reconnect wait to the existing wait tool, bounded by the caller's
wait deadline and client limits. Keep return-on-disconnect available. Retry only
observation of the same command, using backoff or existing connection signals;
never replay execution, stop, terminal input or follow-up actions. Persistent malformed
results need attention, not endless retries. Confirmed boot change ends observation
of the old process. Completion, output saving and controller receipt stay distinct.

**Progress (#223).** Check whether the running image contains the previous fix.
Exercise the actual stream-to-TUI path, including split escape sequences, carriage
returns and terminal widths. Show the latest readable progress without accumulating
old text. Keep raw diagnostics. No second progress system or full terminal emulator.

## Replace generic sequences with explicit conveniences (#241)

Start with the two useful action combinations; keep standalone actions:

- `rpm_ostree_prepare_candidate(after_prepare="stop")` remains the default, for
  artifact inspection. Opt into `"deploy"` or `"boot"` (prepare, deploy, then boot).
- `recovery_deploy_ostree(boot=false)` continues to stop after transfer. `boot=true`
  requests one boot after successful deployment.
- Keep uploads and command execution separate for now. `ssh_command_start` already
  has bounded initial waiting and selected-session execution. Do not add upload/exec
  combinations or arbitrary follow-up lists without demonstrated need.

Expose applicable deployment options (kernel arguments and SELinux choice) and boot
startup timeout directly, with the same validation/defaults as standalone calls.
Use the existing application operations and shared argument handling, not another
parallel set of tool adapters. Preserve all preparation options including removals.
Selected-session commands must still accept `login_session` through their normal tool.

Record explicit follow-up intent and stable child request identities before starting.
Return promptly with one work reference; status/wait shows separate preparation,
deployment and boot work IDs, outcomes and available candidate/run IDs. Failed or
uncertain phases stop progression and retain completed output for inspection.
Recheck the investigation, intended computer, current recovery boot and capabilities
before each physical phase. Offline, paused or retained-run blockers stop the action
with a useful reason; never silently discard an existing deployment or wait forever.

Identical retries reconcile the same work; changed options conflict. A lost reply,
controller restart or cancellation never grants permission to repeat an uncertain
boot. Use existing reconciliation and work cancellation; if continuation is not
safe, show the remaining standalone action instead of inventing another resume engine.
Pause/force-stop still prevent future phases; cancellation cannot undo a committed
boot. Ordinary resume must not unexpectedly start a previously blocked follow-up.

Remove sequence MCP tools, step schemas, adapters and sequence-only tests. No aliases,
migrations or new workflow engine. Keep history/evidence readable through normal
work/results views and do not reset owner data. Replace active examples and guide
text together during implementation; historical release notes remain historical.

Fast connected tests must cover stop-by-default, explicit deploy/boot, preservation
of package removals and other options, phase failure, pause/cancellation, controller
restart and lost boot reply without duplicate execution. Reuse existing deployment
fixtures; no actual image builds or boots are required for these software checks.

## Small additions over existing work

**Incident capture (#236).** An investigation configures a bounded capture script
and its owned evidence paths. Agent and human triggers invoke the same helper with
a stable request ID; Quirkbench records run/boot, trigger origin, observed/injected/
unknown classification, start/end and declared capture order. The script controls
subsystem-specific collection and writer closure. Quirkbench does not infer which
queries alter hardware state.

Publish an independently identifiable initial snapshot using existing file hashes
and transfer records. Append later observations and errors without replacing it.
Expose partial capture and receipt separately. A lost reply reconciles the existing
capture command; even a collector must not be replayed blindly. Missing configuration
is an actionable error. Capture does not automatically restart software or hardware;
force-stop remains available without waiting for collection or upload. No observer
framework, detector catalogue, phase interpreter or intervention-budget engine.

**Desktop delivery (#240).** After fixing sessions, optionally send the existing
ready request through standard desktop notification facilities as the selected user.
Start with notification-only delivery; TUI/CLI answers remain available. Reuse IDs,
readiness, cancellation and late responses. Report unavailable or uncertain delivery;
do not equate notification delivery with acknowledgment. Dismiss/update on cancel
where supported; report limitations. No automatic redelivery, desktop startup or
sound/volume changes. Action buttons can wait if they require another response system.

**Keep awake (#239).** Wrap an ordinary candidate inhibitor in existing bounded
command ownership. Show requested duration, observed active state, expiry and release;
release only the owned inhibitor. Preserve panel blanking and persistent settings.
Verify whether the selected mechanism blocks idle sleep, deliberate sleep, or both;
explicit sleep tests must release it when necessary. Use a deadline unaffected by
wall-clock changes that accounts for suspend, releasing promptly on resume if expired.
Do not claim software executes cleanup while the machine is asleep. Controller loss
must not leave an unbounded inhibitor; restart observes rather than renews it.
If this requires a new scheduler or daemon, defer it and document the ordinary command.

## Integration coverage and native checks

- Session selection: run real application code with an external-command substitute
  that checks supported arguments against captured output. Cover ended, malformed
  and ambiguous sessions. A short native logind check supplements the fast test.
- Observation: one command across controlled disconnect/reconnect, lost stop reply,
  empty/malformed response and boot change. Verify no repeated execution, clear
  errors and bounded waits; release test events instead of sleeping through outages.
- Capture: preserve a transient marker before a state-changing query, then exercise
  duplicate trigger, failed collector and interrupted transfer. Verify original
  hashes, partial evidence and confirmed receipt through real temporary files.
- UI and optional tools: replay progress streams through actual display code; test
  notification fallback and inhibitor expiry with controlled process/clock boundaries.
  Keep a narrow native desktop/inhibitor check separate from the routine suite.

Improve shared test tools when setup becomes repetitive. Do not let permissive mocks
silently accept invalid external-tool arguments again. No routine image builds,
QEMU, audio workloads or timed suspend tests. Native checks establish only the tested
platform; real media updates and target operations need their usual authorization.

## Scope, documentation and completion

Generic command sequences are being removed in 1.3 by owner decision. #241's
adapter fix is superseded; its missing `removals` and `login_session` examples remain
acceptance cases. This replaces the earlier plan to retain sequences pending feedback.

Keep audio detectors, injectors, thresholds and kernel reasoning in investigation
workspaces. No BIOS/internal-disk work, global run timeout, migrations or owner reset.
Implementers may choose ordinary library/tool details. Ask before adding substantial
machinery or reducing capability, speed or ease of use.

Update the agent guide, affected mockups and component sequence with implemented
behavior; examples remain optional. Reuse existing timing and MCP activity records
to assess fewer failed observations, smaller setup scripts and faster useful evidence.
Finish with one independent review, focused tests and clear remaining native checks.
Do not call optional work complete if deferred; record the reason in its issue.


## Delivery

Implemented all seven issues using existing commands, transfer, work records and
native desktop/logind tools. Generic sequences are removed. No owner data reset,
schema migration, automatic controller restart or physical media update is included.
See the [release notes](../release-notes/1.3.md) for verification and update guidance.
