## Architecture and persistence

The existing experiment envelope references a versioned deployment artifact. Composer, deployment backend and boot-control interfaces keep backend details out of scheduling and evidence ownership. The old four-file bundle is retired. Recovery remains independent, candidate mutable state is isolated per attempt, and the target recipe path rejects unsupported deployment or legacy kernel-only execution rather than accidentally running a normal recipe.

Controller database migration is additive. Deployment references pin exact commits before database commit; interrupted pinning can leave extra retained content but cannot authorize an unprotected revision. Checkpoints retain both commits and explicit build evidence. Backup completion requires referenced OSTree object closure and all matching source/symbol artifacts. Restore verifies content and publishes state paused. Source backups are not mutated. `pull-local` hardlinks are detached into durable independent copies to prevent corruption of one repository affecting another.

Target preparation binds its journal to immutable intent, rechecks cached signatures and object integrity, verifies kernel protection configuration and boot-file hashes, and resolves current BLS entries rather than trusting mutable index filenames. Changed trust material requires recommissioning. Cleanup requires matching recorded identity, acknowledged/reconciled evidence, disarmed boot state and an inactive, unpinned deployment. Nested symlinks cannot redirect privileged metadata/repository writes outside the verified external sysroot.

The initial protection profile still excludes internal controllers and firmware-write interfaces; equivalent alternative mechanisms remain possible after review and acceptance. Candidate filesystem execution is permitted separately from restricted evidence storage. Kdump remains unavailable under the current no-kexec policy pending its own reviewed revision and hardware qualification.

## Remaining integration and physical gates

The final image is a QEMU smoke fixture, not a commissioned Acer image. Earlier failed runs and prototype images remain preserved for diagnosis. A shared behavioral suite and real fixtures must continue checking equivalent outcomes rather than relying only on mocked commands.

M3 still owns durable physical attempt handoff, boot reconciliation and evidence upload. The current supervisor intentionally refuses physical deployment execution without that integration. Repository trust/key configuration restoration is an explicit operator prerequisite; credentials are not copied into debugging evidence or target payloads.

Monitoring separates liveness, measured advancement and deadlines. Current OSTree subprocess output counts are not download-byte progress. Complete tool-specific progress and boot-stage reporting before unattended operation. Hardware reset/capture, suspend behavior and the campaign exceeding 30 hours remain M4 qualification; baseline/patched/revert causal evidence remains M5.
