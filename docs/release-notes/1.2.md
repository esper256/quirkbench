# Quirkbench 1.2

Quirkbench 1.2 makes agent investigations easier to follow and cheaper to iterate:
reused candidate layers, compact evidence access, existing-session commands, batch
uploads and explicit human requests. The controller gains an interactive dashboard;
recovery drives can move between computers without mixing their investigations.

See the [changelog](../../CHANGELOG.md#12--2026-10-23) for changes since 1.1 and the
[agent guide](../agent-guide.md) for available tools. Examples are suggestions,
not a required investigation procedure or hardware-specific defaults.

## Updating

- Tag: `v1.2`. Python and RPM package version: `1.2.0`.
- This GitHub release publishes source. No controller RPM or newly checked recovery
  image is attached. Packaging support does not imply published binary assets.
- Stop the foreground controller before updating its software, then start it again.
  Updating a checkout does not update an already running process, flashed recovery,
  or prepared candidate.
- Session selection and human requests need updated target tools. Existing older
  images do not gain them merely by updating the controller.
- `run_results` now defaults to a summary. Use `view="files"`, `"commands"`,
  `"transfers"` or `"collections"` with pagination for details. `saved_output_read`
  supports bounded tail reads. Scripts expecting the old full response must change.
- `--state` is replaced by `--data-dir`; `doctor` is removed. Normal operation uses
  the default user data directory without either option.
- No migrations are supplied. Very early controller records may be incompatible;
  follow the CLI's reset guidance only after retaining any evidence you need. This
  release does not automatically reset data or update media.

The release also fixes #234: the temporary initramfs build-script mount now uses
the same SELinux relabel option as the RPM mounts. The regression fails without
the fix; actual candidate preparation on the reporting host remains to be retried.

## Verification and limits

The implementation passed the full fast integration suite (172 tests), followed
by focused checks after independent review fixes (26 and 30 tests). Tests use real
application code, temporary files, local connections and child processes, replacing
expensive or privileged OS operations. Formatting and static checks passed.

No new recovery build, flashing, QEMU or hardware checks were performed for the
1.2 interaction changes. Matching-source kernel replacement, final initramfs boot,
new session access and human requests still need verification on the intended
hardware. Earlier hardware observations do not establish that every new image works.
