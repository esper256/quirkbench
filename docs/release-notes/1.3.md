# Quirkbench 1.3

This release improves command observation and session access, replaces generic
chaining with two explicit conveniences, and adds optional incident capture,
desktop requests and bounded keep-awake controls. See the [agent guide](../agent-guide.md)
for usage; examples are suggestions, not mandatory investigation procedures.

## Updating

- Tag: `v1.3`. Package version: `1.3.0`.
- Stop the controller before updating, then start it again. Existing processes,
  candidate files and flashed recovery do not update with the checkout.
- Generic `controller_sequence_*` tools are removed. Preparation stops by default;
  choose `after_prepare="deploy"|"boot"`, or deployment's `boot=true`, explicitly.
  Old records remain readable; no migration or automatic continuation is provided.
- Incident capture and keep-awake need new candidate target tools. Desktop delivery
  needs a working notification service and libnotify in the selected existing
  session; unavailable delivery keeps the CLI/menu response path.
- The progress-display fix requires updated recovery. This release does not
  automatically rebuild or flash media, reset data or restart the owner controller.
- Python wheel and source distribution are release artifacts, not a complete
  native installation or a newly checked recovery image. Native packaging remains
  documented separately in [releases](../releases.md).

## Verification

Fast integration journeys use actual controller/target Python, local MCP/SSH,
temporary files and real child processes. They replace image builds, privileged
actions and desktop/logind services. They cover retries, failed observations,
cancellation/restart, partial incident evidence, notification fallback and bounded
sleep ownership. Native desktop delivery, sleep behavior and the updated recovery
display still need checking on the intended hardware. No hardware qualification
is claimed.
